# ═══════════════════════════════════════════════════════════════════════
# T1  重试循环 0x91D412AC —— 闭合
# ═══════════════════════════════════════════════════════════════════════
# 循环体（0x91D412AC..0x91D412FC）：
#   91D412AC  bl 0x91d3c3f0        ; boot 主函数（每次迭代重新执行，G 重新验签）
#   91D412B0  sub r0,r0,#4 ; cmp r0,#5 ; bhi 0x91d4141c   ; 返回值∉[4,9] → 退出
#   91D412BC  lsl r3,r5,r0 ; tst r3,#0x27 ; beq 0x91d4141c ; 允许码 {4,5,6,9}（r5=1）
#   91D412C8  bl 0x91d0aed4        ; 读 [0x92002738]
#   91D412CC  cmp r0,#0 ; beq 0x91d4141c                  ; state==0 → 退出循环
#   91D412D4  mov r0,r4 ; bl 0x91d0a4e4                   ; state!=0 → 处理状态元素
#   91D412DC  bl 0x91d0aed4        ; 底部再读 state
#   91D412E0  cmp r0,#0 ; beq 0x91d412ac                  ; state==0 → 回循环头（再试一次 boot）
#   91D412E8  bl 0x91d0ad64        ; state!=0 → 清理（操作 0x98 字节结构表位域，条件置 [0x9200273C]=1）
#   91D412F0  bl 0x91d0a894 ; cmn r4,#1 ; bne 0x91d412ac  ; r4!=-1 → 再试；==-1 → 退出
#   91D412FC  b 0x91d411b8         ; 退出
# 出口 0x91D4141C：打印 0x91D856E4 = "ERROR: Could not do normal boot. Reverting to fastboot mode.\n"
#                 → b 0x91d411b8（收尾）
# 无计数器/无超时变量（循环核内唯一写是 0x91D412B0 的 sub r0,r0,#4，纯分类）。
#
# 关键全局量 [0x92002738]（循环继续条件）：
#   - 全 PT_LOAD 扫描：movw/movt 物化 1 处（读 @0x91D0AEF4）、literal pool 0 处
#   - 数组基址 0x9200272C/28/30 的引用全部是读取（0x91d0a4e4 / 0x91d0ad64 索引读、0x91D0B088 显示函数）
#   - 无任何写入者 ⇒ crt0 清 .bss 后恒 0
# ⇒ 默认配置下的实际行为：入口 → 底部检查(state==0) → 循环头 boot 尝试(1 次)
#    → 返回分类 → mid 检查(state==0) → 退出循环 → 打印 → **revert to fastboot**。
#   「返回 4 → 重试」形式上存在，但重试分支需要 state!=0，在无写入者前提下不可达。
#   重试链（0x91d0a4e4 → 清理 → 0x91d0a894）是否能收敛：静态上从未被走过，保持开放。
#
# ═══════════════════════════════════════════════════════════════════════
# T3  verify_failure_flag [0x92007DAC] 生命周期 —— 闭合
# ═══════════════════════════════════════════════════════════════════════
# 全二进制引用（movw/movt + pool 全扫）：
#   写 1 处：0x91D39DB4（G 失败分支，mov r1,#1 @0x91D39DA8）
#   读 2 处：0x91D3AD40（打印日志后继续，不阻断）
#            0x91D3C85C（门控读，唯一）
#   清零写：0 处。无 literal pool 引用。
# 生命周期：crt0 .bss 清零(0) → 首次验签失败置 1 → **永久保持，无任何复位路径**。
# 结构性后果（评审 P0 子任务确认）：若门控可达，第一次失败后 flag=1 会污染后续
# 所有 G 调用（含 /recovery 路径的验签结果读取）——跨调用、跨重试残留。
# 但由于门控本身需要 [0x92013AC0]!=0 才会读 flag（见 T5），默认配置下 flag 残留无消费者。
#
# ═══════════════════════════════════════════════════════════════════════
# T4  G 的三个调用点 —— 闭合
# ═══════════════════════════════════════════════════════════════════════
# 调用点 1 @0x91D3C84C（boot 主函数 0x91D3C3F0 内，即回 fastboot 的主流程）：
#   G → bl getter 0x91d445e8 → [0x92013AC0]==0 则跳过 flag 检查继续装载
#                                    → 非 0 才读 flag，flag!=0 → b 0x91d3c58c（return 4）
#   同函数内第二处同模式门控 @0x91D3CC68（subs r3,r0,#0; bne 0x91d3c7f4）。
# 调用点 2 @0x91D3D764（独立流程）：G → b 0x91d3d5e0 → 打印日志 → 继续装载。
#   ±0x200 内无 flag 物化、无 getter 调用。
# 调用点 3 @0x91D3E380（独立流程）：G → b 0x91d3e1f8 → [0x92007BA0]/0x91d45798/
#   0x91d37b10(boot-mode) 检查 → 继续装载。无 flag、无 getter。
# flag 在全二进制仅 1 处读取 ⇒ 门控唯一属于调用点 1 所在的 0x91D3C3F0 流程。
# G 内部 0x91D39DF8 bl 0x91d0aed4 读 boot-state 选择 /boot vs /recovery（三调用点共用 G）。
# ═══════════════════════════════════════════════════════════════════════
# T5  helper 0x91D445E8 语义 —— **修正，撤回 round-2 结论**
# ═══════════════════════════════════════════════════════════════════════
# 实际反汇编（完整）：
#   91D445E8  movw r3,#0x57dc / movt r3,#0x9201   ; r3=&__stack_chk_guard
#   91D445F8  ldr r1,[r3]                          ; canary
#   91D445FC  movw r2,#0x3ac0 / movt r2,#0x9201    ; r2=0x92013AC0
#   91D44608  ldr r0,[r2]                          ; 返回值 = [0x92013AC0]
#   91D44614  cmp(保存值,重读) ; bne 0x91d44624    ; canary 失配 → bl __stack_chk_fail
#   91D4461C  add sp ; 91D44620 pop {pc}           ; return [0x92013AC0]
# ⇒ **0x91D445E8 = 4 条指令纯 getter：return [0x92013AC0]**（+栈保护壳）。
# round-2 所称「慢路径成功返回 0 / 失败返回 -1」错误——那是 **下一个函数 0x91D44628**
# （自有 push 序言；4 个调用者 0x91D44D68/74/80、0x91D45304；错误串
#   'mdtp: mdtp_tzbsp_enc_hash_DIP: ERROR, cannot cipher DIP' ⇒ mdtp 子系统，与门控无关）。
# 「并发一致性检查」的说法**撤回**：那是栈保护模式，非并发检查（评审保留意见正确）。
# [0x92013AC0] 引用全扫：getter 读 1 处 + pool@0x91D4688C 2 处（0x91D46378/BC，
#   属 0x91D46200 倒计时/动画子系统；该处 r8=0x92013AC0 仅作元素基址、从 +4 起读，
#   循环计数 r7 与基址无关）——**未发现任何写入者** ⇒ getter 恒 0。
# ⇒ 门控死：[0x92013AC0]==0 → beq 继续 → flag 永不被读 → 验签失败不影响装载决策。
#
# ═══════════════════════════════════════════════════════════════════════
# T7  [0x920157DC] = __stack_chk_guard —— 以完整模式证据确认（round-2 判定成立）
# ═══════════════════════════════════════════════════════════════════════
# 证据：1653 处 movw/movt 物化，绝大多数紧跟函数序言 ldr（canary 加载）；
#       函数尾部统一模式：ldr(栈保存) + ldr(重读全局) + cmp + bne 0x91d516c4；
#       0x91d516c4 = __stack_chk_fail（0x91D0AED4/0x91D377A8/0x91D37814 等尾部分支一致）。
# guard 存储：0 处 → .bss 恒 0 → 所有 canary 检查恒过、__stack_chk_fail 不可达。
# 附带结论：0x91D0AED4 = 栈保护包裹的 return [0x92002738]；其"双重读比较"就是
# canary 尾部检查，不是并发校验——round-2 的"一致性检查"猜测由此否定。
