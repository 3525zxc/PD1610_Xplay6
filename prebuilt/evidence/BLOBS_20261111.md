## 3. 非 Treble 的三个硬事实（移植必须照做）

1. **`/vendor` 是 `/system/vendor` 的符号链接**，没有独立 vendor 分区。
2. **`/init.rc` 硬编码挂载 system**，所以 ramdisk 里没有 `fstab.qcom`：
   ```
   mount ext4 /dev/block/bootdevice/by-name/system /system ro barrier=1
   ```
   （出现两次，分别在 `on fs` 与 `on late-fs`；`by-name/system` 经 dm-verity 映射为 `/dev/block/dm-0`）
3. **其余分区由 `vendor/etc/fstab.qcom` 挂载**，关键行：
   ```
   /dev/block/bootdevice/by-name/apps      /apps     ext4  ro,barrier=1,discard                      wait
   /dev/block/bootdevice/by-name/oem       /oem      ext4  ro,barrier=1,discard                      wait,verify
   /dev/block/bootdevice/by-name/userdata  /data     ext4  ...,forceencrypt=footer,quota             wait,resize
   /dev/block/bootdevice/by-name/cache     /cache    ext4  noatime,nosuid,nodev,barrier=1            wait
   /dev/block/bootdevice/by-name/dsp       /dsp      ext4  ro,nosuid,nodev,barrier=1                 wait
   /dev/block/bootdevice/by-name/modem     /firmware vfat  ro,...                                    wait
   /dev/block/bootdevice/by-name/bluetooth /bt_firmware vfat ro,...                                 wait
   ```

→ 类原生移植时：`/system`、`/vendor` 的挂载方式要按上面重写；`/apps`、`/oem`、`/dsp` 这些 vivo 专有分区如果 ROM 不用，可以保留挂载但不必放内容；`forceencrypt=footer` 想免解密就改 `encryptable=footer`（酷安文章的做法），但本机现在 BL 已解锁，改 boot 不再触发解密失效。

## 4. ELF 依赖闭包

解析 **1370 个 ELF**（25 个失败均为 `vendor/firmware/*.elf` 固件，无 `PT_DYNAMIC`，属正常）。

| 位数 | 依赖 vendor 之外的库 | AOSP 自带 | 私有需带走 |
|---|---|---|---|
| 32 | 115 | 34 | 8 |
| 64 | 112 | 32 | 7 |

**必须带走的私有系统库**（已抽到 `blobs/extra_system_lib/`）：

```
32 位：com.qualcomm.qti.ant@1.0.so  libtrueportrait.so  libvraudio.so
       vendor.qti.hardware.factory@1.0.so  vendor.qti.hardware.fm@1.0.so
       vendor.qti.hardware.iop@1.0.so  vendor.vivo.hardware.bbkts@1.0.so
       vendor.vivo.hardware.light@1.0.so
64 位：同上但无 libtrueportrait.so（共 7 个）
```

其余 `android.hardware.*@x.y.so`、`libhidl*`、`libbase` 等由 AOSP/LOS 自行编译，不需要从原厂带 —— **但版本必须对得上**，这是 LOS16 移植时最容易踩的坑（例：`android.hardware.camera.device@3.3`、`graphics.composer@2.1` 在 Android 9 里仍存在，可满足）。

**9 个完全找不到的依赖**（设备上就没有，属于编译期可选链接，不影响启动）：

| 库 | 需要它的 blob | 影响 |
|---|---|---|
| `libgcc.so` | 10 个 `lib*_skel.so`（ADSP 侧） | DSP 卸载路径，缺失即该功能不可用 |
| `libmm-dspp-utils.so` / `libmm-qdcm-diag.so` | `libmm-disp-apis.so`、`libmm-qdcm.so` | 显示色彩管理（QDC） |
| `libloc_externalDrcore.so` | `libloc_externalDr.so` ×2 | 定位 DR 引擎 |
| `libtzplayready.so` | 4 个 `libprdrm*` | PlayReady DRM |
| `liboemcrypto.so` | `StoreKeybox` | Widevine L1 keybox |
| `libc++.so.1` / `libc++abi.so.1` | `libhvxMathVIO.so` | HVX 数学库 |
| `libllvd_smore.so` | `libmmcamera_llvd.so` | 低光相机算法 |

→ 移植后这些功能大概率失效（Widevine L1、PlayReady、部分相机算法），属可接受损失，不影响开机与日常使用。

## 6. 缺口与风险

- **`vendor/app`（25 个预置 APK）**：LOS 不需要，建议剔除以减体积
- **`vendor/firmware`（73 个固件）+ `/firmware`、`/bt_firmware` 两个 vfat 分区**：这些是独立分区，ROM 包不要重复放；但 GPU 固件（`a530_*`）在 `vendor/firmware` 里，必须留
- **只解析了 `vendor/`**：`/system/bin`、`/system/lib` 里还有 vivo 私有组件（如 `libtrueportrait`），本轮只带走了被 vendor 直接依赖的那批；后续按实际启动日志补
- **未做 `strings`/`nm` 级验证**：符号完整性（导出符号是否被 LOS 版本满足）要等实际链接/运行时才能暴露
- **`vendor/lib/hw`、`vendor/lib/egl` 子目录已递归包含**，但 `vendor/lib64/hw` 是否有同名冲突未逐一比对
