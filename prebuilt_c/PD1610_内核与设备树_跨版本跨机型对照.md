## 0. 一句话结论

**Xplay6 的原厂 3.18.71 内核在 config 层面已经具备运行 Android 10 的全部子系统，设备树的 fstab 也已声明为「非 Treble（vendor 禁用）」，与 TB8703 上跑通的 LineageOS 17.1 同构。目标 B 的差距不在内核能力，而在 ① 关闭 dm-verity、② 3 个 vivo 私有驱动 + 参数搬运、③ 启动链。**

补充一个意外发现：**vivo 自己把 PD1610 的设备树打进了 PD1516A（Xplay5S）的 boot.img**——两台机器共用同一个内核二进制，靠 `board-id` 选择 DTB。

## 2. 意外发现：PD1516A 7.7.6 的 boot.img 内含 PD1610 设备树

`pd1516a_776\boot.img` 里**只有 3 份 DTB，全部是 vivo 自己的**：

| 索引 | model | compatible | msm-id | board-id | pmic-id |
|---|---|---|---|---|---|
| 0 | `vivo MSM 8996 v3 + PMI8996 PD1516` | `qcom,msm8996-cdp` | `<0xf6 0x30001>` | `<0x1 0x9 …>` | `<0x20009 0x20009 …>` |
| 1 | `vivo. MSM 8996 v3 + PMI8994 PD1516A` | `qcom,msm8996-cdp` | `<0xf6 0x30001>` | `<0x1 0x9 …>` | `<0x20009 0x2000a …>` |
| **2** | **`vivo MSM 8996 v3 + PMI8996 PD1610`** | `qcom,msm8996-cdp` | `<0xf6 0x30001>` | **`<0x1 0xa …>`** | **`<0x20009 0x10013 …>`** |

**含义（已确认）**：

- **vivo 对 MSM8996 采用「单内核 + 多 DTB」**：一个 boot.img 同时服务 PD1516 / PD1516A / PD1610，启动时由 aboot 用 `msm-id` + `board-id` 匹配选表（PD1516A=`0x9`，PD1610=`0xa`，msm-id 相同）。
- 这直接说明 **PD1610 与 PD1516A 的内核二进制是可互换的**（同一份代码）；差异只在 DTB 与驱动参数。
- 对照：PD1516A **3.8.5** 的 boot.img 有 59 份 DTB，**全部是高通参考板（apq8096-cdp / msm8996-cdp / msm8996-mtp 等），没有一份 vivo 定制**。⇒ vivo 在 3.8.5 → 7.7.6 之间，从「高通参考 DTB 集合」切换成了「自建 vivo DTB 集合」。这是他们自己的一次设备树重构。

## 4. PD1610 设备树的版本演进（7.7.6 → 8.19.16）

**新增（137 个，关键项）**：

- `/firmware/android/fstab` + `system` + `vendor` —— **Android 8+ 的「DT 传递挂载表」机制**（见 §6）
- `/soc/android_usb1`（第二路 USB 控制器）
- `/soc/i2c@75b5000/{qcom,camera@2, qcom,eeprom@0x50, qcom,actuator@0x72, ncp6335d-regulator@68}` —— 摄像头子系统补全
- `/soc/dsi_panel_pwr_supply_vdd_no_labibb`、`…_no_labibb/panel-supply-entry@1` —— 屏幕供电分支
- 大量 `pinctrl`（blsp1_uart5 / blsp2_uart1/3/6、cam_sensor_mclk3）

**删除（19 个，关键项）**：

- `/soc/pinctrl@01010000/fpc_irq`、`fpc_reset` —— **FPC 指纹的引脚定义**
- `/soc/switch_gsensor` —— 传感器切换开关
- `/soc/qcom,cci@a0c000/qcom,camera@2`、`/soc/qcom,mhi`
- `/soc/dsi_panel_pwr_supply_amoled/panel-supply-entry@{1,2,3}`

**判读（较强推断）**：7.7.6 时代的 PD1610 DTB 里 **`fpc_irq`、`switch_gsensor` 各出现 2 次 / 1 次**，而 8.19.16 版**完全为 0**——这些是 Xplay5S（PD1516A）的硬件残留。说明当时 PD1610 的设备树是**从 PD1516A 复制修改而来**，到 8.19.16 才清理干净。同时指纹方案从 FPC 换成了 `CONFIG_BBK_GF5116M`（汇顶 GF5116M，见 config）。

## 6. 关键：`/firmware/android/fstab` 对照 —— 目标 B 的具体改法

### 6.1 PD1610 8.1 原厂（现状）

```dts
firmware {
    android {
        compatible = "android,firmware";
        fstab {
            compatible = "android,fstab";
            vendor {
                compatible = "android,vendor";
                dev = "/dev/block/platform/soc/7464900.sdhci/by-name/vendor";
                type = "ext4";
                mnt_flags = "ro,barrier=1,discard";
                fsmgr_flags = "wait";
                status = "disabled";        ← 禁用
            };
            system {
                compatible = "android,system";
                dev = "/dev/block/platform/soc/7464900.sdhci/by-name/system";
                type = "ext4";
                mnt_flags = "ro,barrier=1,discard";
                fsmgr_flags = "wait,verify"; ← dm-verity 开启
                status = "ok";
            };
        };
    };
};
```

### 6.2 TB8703 LOS 17.1（跑通的 Android 10 参考）

```dts
firmware { android { fstab {
    system {
        dev = "/dev/block/platform/soc/7824900.sdhci/by-name/system";
        type = "ext4";
        mnt_flags = "ro,barrier=1,discard";
        fsmgr_flags = "wait";               ← 没有 verify
        status = "ok";
    };
    /* 完全没有 vendor 节点 */
}; }; };
```

### 6.3 三条可直接执行的结论

1. **PD1610 的 `vendor` 在 8.1 就是 `status = "disabled"`** ⇒ 原厂就是**非 Treble**。这与 TB8703 一致，说明 **Android 10 走「system-only 非 Treble」路线在结构上是原厂自洽的**，不需要造 vendor 分区。
2. **移植时必须把 `system` 的 `fsmgr_flags` 从 `"wait,verify"` 改成 `"wait"`**（关 dm-verity），否则自编译 system 会因 verity 校验失败而无法挂载。这是 TB8703 已经验证过的做法。
3. TB8703 的 ramdisk 只有 `apex/ dev/ debug_ramdisk/ init` 四个条目、**没有 fstab 文件** ⇒ 它完全依赖 DT 里的 fstab。**PD1610 也应当用同一机制**：DT 提供 fstab，ramdisk 不做第一段。这省掉了自己写 first-stage init 的工作。

**结论**：

1. **Android 10 所需的内核子系统，PD1610 原厂一个不缺**（binder/ashmem/ION/SDCardFS/SELinux/dm-verity/dm-crypt/zram 全在）。config 层面的「Android 10 差距」**接近零**。
2. **两版都没有 `FS_ENCRYPTION`** ⇒ 都没有 FBE（文件级加密）。TB8703 用「不加密 / FDE」跑通了 Android 10 ⇒ **PD1610 也可以不加密运行**，但要在 fstab 与 `ro.crypto.state` 上对应处理。
3. **PD1610 没有 F2FS**，但 TB8703 的 fstab 用的也是 **ext4** ⇒ 不需要补 F2FS。
4. `DM_VERITY_FEC=y` 是 PD1610 独有（前向纠错），对我们无影响（关 verity 后不用）。

## 9. 驱动存在性核验：86.3%

方法：DTS 中 292 个唯一 `compatible` 字符串，逐个在**原厂内核镜像**里查找（`of_match_table` 的字符串字面量会保留在 .rodata）。

| 结果 | 数量 | 占比 |
|---|---|---|
| 内核镜像中存在 | **252** | **86.3%** |
| 未找到 | 40 | 13.7% |

**未找到的 40 个，逐类判读**：

- `android,firmware` / `android,fstab` / `android,system` / `android,vendor`（4 个）—— **AOSP 伪节点**，由 bootloader/init 读取，不需要内核驱动 ✓
- `qcom,dsi-*`、`qcom,sde-kms`、`qcom,display-manager`、`smmu_kms_*`、`qcom,hdmi-*`（约 12 个）—— 高通显示驱动**用自己的 DT 解析器**，不进 `of_match_table`，字符串不在镜像里属正常 ✓
- `arm,coresight-*`、`qcom,cpuss-dump`、`qcom,dcc`、`qcom,jtag*`、`qcom,mcd`、`qcom,glink-qos-config` 等 —— 调试/追踪类，多数按 config 关闭
- `micrel,ks8851`、`pps-gpio`、`onnn,ncp6335d-regulator` —— 确实未编入（`ncp6335d` 是摄像头供电 regulator，需另行确认是否走 regulator-fixed 替代）

⇒ **原厂 3.18.71 内核对 DTS 所描述硬件的覆盖是完整的**（86.3% 直接命中，其余多为解析方式不同或调试项）。这再次支持：**移植工作量在参数搬运与 Android 版本补丁，不在写驱动。**

### 12.1 一个反直觉的事实：6.0.1 的 DTB 全部挂着高通的名字

boot.img 内共 **106 份 DTB，`model` 全部是「Qualcomm Technologies, Inc. …」（APQ8096 / MSM8996 / LiQUID / MTP / CDP 等），没有一份写着 vivo 或 PD1610**。

但逐份扫描 `es9038` / `tfa98` / `es9028` 字符串后，**有 3 份带 Xplay6 的音频硬件**：

| 索引 | 大小 | board-id | pmic-id | msm-id | 归属 |
|---|---|---|---|---|---|
| 14 | 358,820 | `<0x1 0x9 …>` | `<0x20009 0x10013 …>` | `<0xf6 0x30001>` | PD1516 系 |
| **43** | **365,941** | **`<0x1 0xa 0x1000001 0x0>`** | **`<0x20009 0x10013 0x0 0x0>`** | **`<0xf6 0x30001>`** | **PD1610** |
| 80 | 358,308 | `<0x1 0x9 …>` | `<0x20009 0x2000a …>` | `<0xf6 0x30000>` | PD1516A（v2） |

⇒ **1.15.1 里 Xplay6 用的是第 43 份**（board-id / pmic-id 与 8.19.16 的 PD1610 分片完全一致），只是 `model` 名没改，仍叫「Qualcomm Technologies, Inc. MSM 8996 v…」。**仅凭 model 名找不到 vivo 的 DTB，必须按 `board-id` + 硬件字符串定位。**

### 12.2 音频参数跨版本稳定（重要）

对比 6.0.1（第 43 份）与 8.1（第 79 份）的音频节点：

| 属性 | 6.0.1 (1.15.1) | 8.1 (8.19.16) | 是否相同 |
|---|---|---|---|
| `compatible` | `ess,es9038` | `ess,es9038` | ✓ |
| `reg` | `0x48` | `0x48` | ✓ |
| `i2s-master` | 有 | 有 | ✓ |
| `vivo,param-num` | `<4 4>` | `<4 4>` | ✓ |
| **`vivo,params`** | `16 27 40 7f 16 40 5f 7f 5 2 1 0 0 0 1 0` | **完全相同** | ✓ |
| `tfa98xx-version` | `tfa9890` | `tfa9890` | ✓ |
| **`tfa98xx-config`** | `tfa98xx_PD1610.cnt` | **相同** | ✓ |
| 阻抗 / 频响 / Qt | 630–950 / 700–950 / ≥125 | **相同** | ✓ |
| GPIO phandle 编号 | `<0x37 …>` | `<0x1a …>` | ✗（仅编号不同，物理 GPIO 相同） |

⇒ **Xplay6 的音频参数从首发到 8.1 一字未改**，是稳定的板级常量：`vivo,params` 16 字节滤波器系数与 `tfa98xx_PD1610.cnt` 可直接作为最终参数使用，不需要在版本间做取舍。

### 12.3 vivo 设备树的演进（完整四代）

| 固件 | 时间 | DTB 总数 | vivo 命名 | 特征 |
|---|---|---|---|---|
| **PD1610 1.15.1** | 2016-12 | 106 | **0** | 改高通参考 DTB，`model` 不改名；PD1610 = 第 43 份 |
| PD1516A 3.8.5 | 2017-05 | 59 | 0 | 全部高通参考，**无 vivo 音频** |
| PD1516A 7.7.6 | 2017-08 | **3** | **3** | 首次自建并改名，1 份 PD1610 混在其中 |
| PD1610 8.19.16 | 2018-11 | 122 | 1 | PD1610 独立 1 份（第 79），其余为高通参考 |

**判读**：vivo 的设备树策略在两年内换了三次（改参考板 → 自建 3 份 → 又扩回 122 份并单列 PD1610）。**对我们唯一有意义的是 8.19.16 的第 79 份**——它是最新、最完整、且独立命名的 PD1610 设备树。
