## 1. 阶段 0：只读备份（**必做，无备份不得进入下一阶段**）

目的：把整条启动链原样导出，确保任何一步都能回到起点。**本阶段只发读命令，不写设备一个字节。**

### 1.1 进入 9008

优先用 adb（若系统能起来）：

```
adb reboot edl
```

若 adb 不可用：**关机 → 按住「音量上 + 音量下」不放 → 插 USB**（vivo MSM8996 的 EDL 组合）。

设备管理器应出现 `Qualcomm HS-USB QDLoader 9008 (COMx)`，记下 COM 号。

### 1.2 执行只读回读（一条命令）

```
C:\qfilx\backup\run_readback.bat COM5
```

（把 `COM5` 换成实际的 9008 端口号）

脚本内部做两件事，可按需手工执行：

```
QSaharaServer.exe -u \\.\COM5 -s 13:C:\qfilx\prog_emmc_firehose_8996_ddr.elf
fh_loader.exe --port=\\.\COM5 --sendxml=readback_program.xml --convertprogram2read ^
   --search_path=C:\qfilx\backup --mainoutputdir=C:\qfilx\backup ^
   --memoryname=eMMC --noprompt --zlpawarehost=1 --showpercentagecomplete --reset
```

输出到 `C:\qfilx\backup\backup_<分区>_LUN<n>.bin`。

**22 个分区清单（GPT 实测值，扇区 4096 B）**：

（`boot` / `recovery` 必须一起备份：11-08 那次 `fastboot flash boot` 被中断，**盘上 boot 的真实内容未知**。）

### 1.3 备份完整性校验（关键，决定后面怎么走）

```bat
certutil -hashfile C:\qfilx\backup\backup_aboot_LUN4.bin SHA256
certutil -hashfile C:\qfilx\backup\backup_devinfo_LUN4.bin SHA256
certutil -hashfile C:\qfilx\backup\backup_boot_LUN4.bin SHA256
```

**三项判读**：

1. **确认设备当前装的是哪一代 aboot** —— 在 aboot 备份里搜字符串：
   - 含 `Device is tampered` → **7.x 代**（1.15.1 / 7.13.15，验签失败=assert 重启）
   - 不含 → **8.x 代**（8.19.16，失败不阻断，**H1 可能已经"意外达成"**）
2. **`devinfo` 前 16 字节应为 `ANDROID-BOOT!`**；`+0x10` 应为 1（已解锁）。
3. **`boot` 是否仍为原厂 6.0.1**：与 `C:\qfilx\boottest\boot_00_baseline.img` 比对 sha256；若不同，说明 11-08 的写入留下了残留，先记下来再决定。

> 若回读失败：**停止**，不要做任何写操作。把 `port_trace.txt` 末 50 行发回来。

## 2. 阶段 1：只刷 aboot（最小改动）

保留现有 6.0.1 系统与 boot，只替换 aboot。

### 2.1 fastboot 方式（首选）

```
fastboot devices
fastboot flash aboot C:\qfilx\firmware\81916\emmc_appsboot.mbn
fastboot reboot
```

### 2.2 失败则用 EDL 方式

QFIL → Flat Build → 只勾选 `aboot`（program XML 中仅保留 aboot 一条），Programmer 选 8996 firehose。

### 2.3 判定 A

| 现象 | 含义 | 下一步 |
|---|---|---|
| 正常开机进系统 | aboot 与旧 xbl/tz 兼容 | 进入阶段 4 |
| 卡 logo / 反复重启 | 链版本不匹配 | 进入阶段 3 |
| 黑屏无反应 | 同上，或 aboot 崩溃 | 进入阶段 3；必要时回滚 |

## 3. 阶段 3：整链刷（仅当阶段 1 失败）

把启动链成套替换（全部取自同一 8.19.16 包）：

```
fastboot flash xbl        C:\qfilx\firmware\81916\xbl.elf
fastboot flash aboot      C:\qfilx\firmware\81916\emmc_appsboot.mbn
fastboot flash tz         C:\qfilx\firmware\81916\tz.mbn
fastboot flash keymaster  C:\qfilx\firmware\81916\keymaster.mbn
fastboot flash cmnlib     C:\qfilx\firmware\81916\cmnlib.mbn
fastboot flash cmnlib64   C:\qfilx\firmware\81916\cmnlib64.mbn
fastboot flash hyp        C:\qfilx\firmware\81916\hyp.mbn
fastboot flash pmic       C:\qfilx\firmware\81916\pmic.elf
fastboot flash devcfg     C:\qfilx\firmware\81916\devcfg.mbn
fastboot flash rpm        C:\qfilx\firmware\81916\rpm.mbn
fastboot reboot
```

> 注意：`fastboot flash xbl` 若报 `partition not found`，改走 EDL + program XML。
> xbl 分区在 LUN1（不是 LUN4），EDL 写时 `physical_partition_number=1`。

## 4. 阶段 4：H1 判定实验（关键一步）

前提：阶段 1 或 3 已确认"换 aboot 后能正常开机"。

### 4.1 准备测试镜像

用已有基线 `boot_00_baseline.img`（原厂 1.15.1 boot）复制一份，**只改 1 个字节**（放在 padding 区，避免破坏结构）：

```
python C:\qfilx\exp\...\patch_one_byte.py  # 沿用 11-08 实验脚本
```

### 4.2 刷入并观察

```
fastboot flash boot <改过的 boot.img>
fastboot reboot
```

### 4.3 判据（**只看这一条**）

| 现象 | 结论 |
|---|---|
| **仍然卡 logo / 5 秒一次重启循环** | **H1 证伪** —— 阻断不在 aboot（回到 13.4 四条件） |
| 黑屏但仍需长按电源才重启（非自动循环） | 进入内核早期但崩溃 —— **H1 成立**（已越过验签拦截） |
| 出现内核日志 / 开机动画 / 进入系统 | **H1 完全成立** |

> 判定依据：7.13.15 下改 1 字节 = tampered assert 重启循环（周期性重启、约 5 秒一轮）。
> 8.19.16 若真的"不阻断"，现象应当**明显不同**（不会有周期性自动重启）。

### 4.4 对照实验（建议同轮完成）

刷回原厂未改动的 `boot_00_baseline.img`，确认能正常开机 —— 排除"是镜像本身坏了"的干扰。

## 5. 回滚

| 场景 | 操作 |
|---|---|
| 只换了 aboot | `fastboot flash aboot C:\qfilx\backup_YYYYMMDD\aboot_LUN4.bin`（16 MB 整分区镜像可直接写） |

## 7. 边界与已知风险

- **未验证**：aboot(8.19.16) 与 XBL(7.x) 的加载接口；静态不可判定（§21.5）。
- **未验证**：8.19.16 aboot 引导 6.0.1 boot.img 的实机表现（格式路径一致，理论可行）。
- **风险**：换 xbl 后若 PBL 拒绝（理论上不会：同 OEM 密钥、升级方向），仍可 9008 恢复（EDL 在 PBL ROM 中）。
- **禁止**：在未完成阶段 0 备份前执行任何写操作。
- **禁止**：同时改多个变量（aboot + boot + devinfo 一起动），否则无法归因。
